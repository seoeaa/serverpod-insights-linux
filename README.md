# Serverpod Insights Linux

Независимый Linux-клиент для **Serverpod Insights 4.0.4**. Версия приложения: **0.1.1**.

## Возможности

- Несколько ручных подключений к Insights.
- Сессии, фильтры endpoint/ошибок, поиск и постраничная загрузка по ID.
- SQL-запросы, сообщения и stack trace выбранной сессии.
- Метрики за последний час и автообновление каждые 10 секунд.
- Настройки логирования с подтверждением и перечитыванием после сохранения.
- Русский интерфейс, светлая/тёмная тема и компактная навигация.

SQL-консоль, очистка серверных логов и автоматический SSH не реализованы.

## Сборка и запуск

Проверенная среда: Linux x86-64, Flutter 3.47.4 / Dart 3.13.3, GTK3 3.24.41. Для сборки нужны C++ toolchain, CMake, Ninja, pkg-config и development-заголовки GTK3. Flutter должен быть доступен в `PATH`.

```bash
flutter pub get
flutter analyze
flutter build linux --release
./build/linux/x64/release/bundle/serverpod_insights_linux
```

Для переноса на другую машину копируйте **весь** каталог `build/linux/x64/release/bundle`, включая `lib/` и `data/`, а не один исполняемый файл. Сборки для ARM64 и дистрибутивные пакеты пока не проверялись.

## Подключение

1. Укажите адрес **Insights-сервера**, а не основного API приложения. Пример локального адреса: `http://localhost:8081/`.
2. Введите собственный `serviceSecret` сервера. Клиент не содержит готовых секретов или подключений.
3. HTTP разрешён только для loopback-адресов. Для удалённого сервера используйте HTTPS с доверенным сертификатом или заранее настроенный локальный SSH-туннель. Redirect запрещён.
4. По умолчанию секрет хранится только в памяти до выхода. Явное включение сохранения использует Linux Secret Service (`org.freedesktop.secrets`); для этого нужны сессионная D-Bus шина и доступная связка ключей. Открытого fallback нет.

Локально сохраняются только метаданные подключений и тема. После закрытия окна автообновление останавливается; отдельного фонового сервиса нет.

## Безопасность и ограничения

- Сервисный секрет даёт административный доступ к Insights: используйте только свои серверы и защищайте их сетевой доступ.
- История сессий зависит от серверного persistent logging. Пустой список не обязательно означает ошибку клиента.
- SQL, логи и stack trace могут содержать чувствительные данные; проверяйте их перед публикацией.
- Запись настроек передаёт полный объект с сохранением скрытых полей и overrides. Сервер не предоставляет optimistic locking: одновременное редактирование несколькими администраторами может конфликтовать.
- Таймаут записи означает неизвестный исход, а не гарантированный отказ; автоматический повтор не выполняется.
- Гарантированное обнуление Dart-строк с секретом невозможно.

Проверены анализатор, Linux release build, нативный запуск и чтение метрик существующего Serverpod 4.0.4. Запись настроек и сценарии пагинации проверялись отдельно на первоначальном стенде 4.0.0; полный повтор этих сценариев на 4.0.4 не заявляется.
